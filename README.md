# Tradejournal Futures

NQ and ES: research, validate and paper trade intraday / swing strategies on CME Globex data from Databento. One AWS SAM stack.

## Pages
- **Running**: NQ / ES tiles, risk used today, the strategies paper trading, today's fills.
- **Chart**: candles 1m / 5m / 15m / 1h, session VWAP, prior-day and overnight levels, volume profile, delta, WaveTrend [Krypt], a strategy's trades drawn on the chart, and **replay** of a session bar by bar with its footprint, volume at price and big-print tape.
- **Research**: every strategy and its stage. New strategies from four setups: opening range break + FVG retest, range 50% retrace, ICT Silver Bullet, WaveTrend dots.
- **Strategy**: the protocol, always the same: Data → Study → Validation (train 60% / test 40%, random-entry baseline, 2× costs, 5 gates) → approved market conditions → Paper (simulated, kill switch) → Live (needs a futures broker: not yet).
- **Fractal**: the TradeWellX Wave [N] rebuild (`backend/fractal.py`): MA vector, pivot, H/L wave counts, Direction, percent-probable clusters and the Option Analyzer wave odds. QQQ / stocks from Alpaca, NQ / ES from the stored Databento candles.
- **Earnings**: the fundamentals side (`backend/fundamentals.py`). **Screen**: revenue 3Y CAGR (TTM), TTM YoY, quarter YoY / QoQ, YoY acceleration, EPS YoY and inflection flags (TTM EPS turned positive, EPS growth turned up / accelerating, revenue accelerating), earnings quality (CFO / NI, Sloan accrual ratio) from SEC EDGAR XBRL; Q4 and quarterly cash flow derived from the 10-K / year-to-date figures. **Company**: 16 quarters and every 8-K item 2.02 release with its reaction (gap, day 0, vs benchmark, σ, 5 / 20 days, drift). **Event study**: your own release CSV (consensus, actuals, guidance, any extra signal columns) plus the 8-K dates of the screen's tickers; reactions from Alpaca split-adjusted daily bars; grouped by beat / raise, guidance, terciles of every signal, with N / mean / median / hit rate / t and a Spearman signal → reaction matrix; CSV export. **Financial Modeling Prep** (your key, Data page; plan check shows what it includes): consensus / actual EPS and revenue, report timing, the next scheduled release, the S&P 500 list (+ removed members). **Before the release**: returns 1 / 5 / 21 / 63 sessions vs the benchmark, 50 / 200-day trend, volume vs the 50-day average (1 / 5 / 20 days), accumulation (Chaikin money flow, on-balance volume), consensus growth, own past reactions. **Forward-looking model** (`backend/model.py`): signals ranked against the previous year's releases (trailing percentiles, no look-ahead), ridge regression tested walk-forward (no look-ahead) for day 0, the size of the day-0 move, 5 days, 1 and 2 months (before the release) and the drift after day 0; scorecard per target and a verdict; the tested model is applied to each company's next release on the Company tab, with the expected size of the move next to the options-implied move (Alpaca at-the-money straddle). A fixed post-release score (EPS / revenue surprise, call tone, tone change, revenue acceleration, low accruals) is scored on the 1- and 2-month drift. **After the call** model: from the day-0 open (exact benchmark open) to the close and to 5 days, using the reported numbers, surprises, the gap and the call (after-close releases only, so no call runs past the open). **Today** tab: the universe's releases reacting at a day's open, with the post-release score band, the call, the gap, the model's expectation and the flags “bad news + gap up” / “good news + gap down”. **Analysts**: upgrades − downgrades in the 30 / 90 days before each release; consensus price target (next release only). **Call transcripts** (FMP Ultimate; `backend/sentiment.py`): downloaded during the study and kept in S3 for good; tone (prepared remarks vs Q&A), uncertainty, guidance raise / maintain / lower from the outlook sentences, change vs the previous call; viewer on the Company tab; call-derived guidance fills beat-and-raise when your CSV has none. **Valuation** (FMP quarterly ratios: P/E, earnings yield, P/S, P/B, P/FCF, PEG, margins, debt / equity) on every release; **What separates winners from losers**: every study signal split in thirds on the backtest's and the real-option trades, checked on both halves of the period. **ETF** page (`backend/etf.py`, `frontend/etf.js`): correlation matrix of daily log returns over 20 / 60 / 120 / 250 days for an editable list (default: sector, industry, commodity and country ETFs — no broad index, no bond fund), grouped by similarity. **ETF pairs** (`backend/etfpairs.py`): every pair of the ETF list traded on the z-score of its log price ratio (entry / exit / stop / hold, only when the 60-day correlation is high enough), decided on a close and traded at the next open, dollar-neutral; train / test (last 5 years), optimizer (216 settings, ranked on train), today's z and signals. **Two universes** (`backend/space.py`): Earnings SPY (S&P 500 vs SPY, the original keys) and Earnings QQQ (Nasdaq-100 vs QQQ, `?u=qqq`, files under `fund/u/<sub>/qqq/`), each with its own settings, study, model, backtest, optimizer and real-option results; filings and price files are shared. **Strategy backtest** (`backend/backtest.py`): legs A–D at a fixed stake per trade over the study's releases, the last 5 years as test; C and D enter at the day-0 close or open and exit on a stop, a trailing stop or a profit target (from the stock's daily bars after day 0, saved once per study) or after up to 60 sessions, as the stock or as a Black-Scholes-priced call / put (the stock's 20-day volatility × a multiplier, spread in % of the premium; no historical option quotes). **Real option prices** (`backend/optreal.py`, Unusual Whales): every C / D trade since 2022 re-priced with the contract listed that day nearest to the expiry / strike settings, bought at the NBBO ask and sold at the bid (mid shown), next to the model; the real implied volatility / model volatility ratio sets the multiplier for the earlier years. Setup filter toggles on C (beat SPY 1m, cash > earnings, guidance raised, market up, no Jan–Apr, no weak sectors, no heavy volume) and D (calm market, gap down, EPS miss, guidance not raised). Optimizer in four stages (entries, setup filters, exits, option): entries, then exits on the best entry, then the option on the best exits, each ranked on train only. `SEC_USER_AGENT` (optional) overrides the User-Agent sent to SEC (default: your sign-in e-mail).
- **Swing** (`backend/swing.py`, `frontend/swing.js`): the **Turtle** breakout (System 1: 20-day high / 10-day low, System 2: 55 / 20; stop k × N with N the 20-day ATR; optional pyramid +1 unit every ½ N up to 4, shorts, skip-after-winner, market filter) and **Qullamaggie's breakout** (ADR, prior 30- or 60-day move, $ volume ≥ $10M by default, above the 50-day with the 10 over the 20, tight base; entry on a break of the base high; stop at the entry-day low, skipped if wider than one ADR; partial sale on day 3–5 then breakeven; the rest out on a close below the 10 / 20 / 50-day average; market filter; position size from a compounding account — default $10,000, 1% of the account risked per trade ÷ the stop distance, at most 25% of the account in one position, no margin — or a fixed $) over the **whole US market** (default for Qullamaggie, `backend/allstocks.py`: FMP company screener — NYSE / NASDAQ / AMEX, no ETF or fund — plus FMP delisted companies since 2016, bars cut at the delisting; Alpaca daily bars 50 symbols per request; kept if ever $5M+ a day at $3+; shards of 100 symbols), the S&P 500, the Nasdaq-100 (removed members included), both, or the ETF list, since 2016. Turtle on **futures** (default, `backend/futdaily.py`): 30 CME markets (equity index, rates, metals, energy, grains, meats, currencies; ICE softs not on Globex) from Databento GLBX ohlcv-1d since June 2010 — one request per market for every contract (parent ROOT.FUT, spreads dropped, all markets in parallel), the front picked as the most traded contract rolled only forward, back-adjusted at each roll (fallback: continuous ROOT.v.0 / v.1); unit = $ risk ÷ (N × $ per point) contracts, fractional or whole, commission and slippage ticks per contract; by market group. Turtle account (futures, default): start equity (default $1M), each unit = 1% of the equity per 1 N move, compounding on closed trades, at most 12 units long / 12 short (adds beyond it not taken), whole or fractional contracts; CAGR, max drawdown (closed trades), returns by year, a fresh account for the test period. Optimizer: 24 settings (System 1 / 2, 2 / 3 / 4 N stop, pyramid, shorts) with every market group's train / test stats to choose groups on train only. Train / test (last 5 years), R multiples, by year, by exit reason, best / worst symbols, equity, open positions, next-session watchlist, CSV; optimizer (32 / 128 settings × every symbol, ranked on train). Background job.
- **Beat the Market** (Swing page tab; `backend/intramom.py`, `frontend/intramom.js`): Zarattini, Aziz & Barbon's SPY intraday momentum — noise area from the average move from the open at each time of day over 14 sessions (gap-adjusted, × VM), checks every 30 minutes (15 / 60 options), stop at the opposite band, the current band, or the current band / VWAP, flat at 16:00, 100% or volatility-target sizing (2% ÷ 14-day σ, max 4×), $0.0035 + $0.001 a share; SPY 1-minute bars from Alpaca since 2016 (stored by month), VIX daily from FMP (regime table and an optional VIX filter), day of week, 5-day RSI, long vs short, vs SPY buy & hold; train / test (last 5 years); optimizer (216 settings, train Sharpe).
- **Data**: connect Databento and Alpaca (keys stored encrypted with KMS); Databento (key stored encrypted with KMS), download 1-minute candles and trades (footprint) with the cost shown first, automatic refresh every 15 minutes in the session and the day's trades after the close.

## Workspace (new direction): chart + AI + Pine + paper trading
`workspace/` is a TradingView-style trading workspace that runs next to the existing app (nothing above was removed). It needs a small always-on server instead of Lambda, because the charts stream live candles.

    npm run workspace                      # http://localhost:8765 (simulated data, demo AI)
    ALPACA_KEY_ID=... ALPACA_SECRET_KEY=... ANTHROPIC_API_KEY=... npm run workspace

| Piece | Where |
|---|---|
| Server (`workspace/server/server.py`): web app, history at any timeframe, live stream (server-sent events), paper broker, Claude proxy | One process, Python 3 standard library only |
| Live data (`market.py`) | Alpaca WebSocket (`wsclient.py`, trades + minute bars, stocks and crypto) → current 1-minute bar → every open chart; REST for history. No keys: deterministic simulated market that ticks 4× a second |
| Chart (`web/chart.js`) | Canvas, no library. Wheel = zoom time around the cursor, drag = pan time and price, drag the price scale = zoom price, drag the time scale = zoom time, double-click price scale = auto. Panes per oscillator (resizable), candles / hollow / bars / Heikin Ashi / line / area, crosshair, last-price countdown, older history loads as you scroll left |
| Pine Script (`web/pine.js`) | Interpreter for a large v5 / v6 subset: `var`, tuples, `if` / `for` / `while` / `switch`, functions, history `[]`, ~60 `ta.*`, plots / shapes / fills / bgcolor / barcolor, `line` / `label` / `box`, arrays, methods. Editor with highlighting, errors by line, Ctrl+Enter to run, saved scripts |
| Indicator library (`web/library.js`) | 33 scripts written in Pine (Volume, MAs, VWAP, BB, Supertrend, Ichimoku, RSI, MACD, ADX, PDH / PDL, opening range, pivots, Smart Money Concepts with BOS / CHoCH / EQH / EQL / order blocks, FVGs, signals): search, families, favorites, previews, open the source and fork |
| AI chat (`web/chat.js`) | Claude through the server (`llm.py`, key stays on the server). It gets a screenshot of the chart with each message plus the chart state, and tools: read bars (any symbol / timeframe), draw levels / zones / trend lines, change symbol / timeframe, add indicators, write Pine (compile errors are fed back so it fixes them), read the account, place paper orders (with a confirmation card) |
| Paper trading (`paper.py`) | Market / limit / stop, bracket stop-loss + take-profit (OCO), longs and shorts, buying-power check, kill switch, ask-before-placing, order lines on the chart you can drag to modify, positions / orders / fills / closed trades (CSV) |
| Workspace | Chart tabs (symbol + any timeframe: 1m … 22m … 4h … 1D 1W 1M), watchlist with live prices, drawing tools (trend, horizontal line / ray, vertical, rectangle, text, measure, magnet, undo), bar replay, object tree, ranges (1D … All). Layout, scripts and drawings are saved on the server (`workspace/.data/`) |

Environment: `DATA=fake|alpaca`, `ALPACA_FEED=iex|sip`, `CLAUDE_MODEL` (default `claude-sonnet-5-5`), `WORKSPACE_PASSWORD` (HTTP basic auth: set it whenever the server is reachable from the internet), `HOST`, `PORT`, `DATA_DIR`.

Deploy: push to `main`. After the main stack, `deploy.sh` deploys the `<STACK>-workspace` stack (`workspace/infra/workspace.yaml`: one t4g.micro running the server under systemd, CloudFront in front for HTTPS, code and data backups in its own S3 bucket), uploads the code and restarts the service. Keys: Alpaca comes from the journal's Data page (the server decrypts the stored key with the app's KMS key at every start; live stream on IEX, real time on the free plan); Claude comes from the `ANTHROPIC_API_KEY` GitHub secret (the workflow passes it to `deploy.sh`, which stores it in SSM `/tradejournal/workspace/`). `WORKSPACE_PASSWORD` and `ORIGIN_SECRET` are generated in SSM on the first deploy (the server refuses requests that don't come through CloudFront). The workspace URL is printed at the end of the deploy log. `workspace/Dockerfile` is there for other hosts. Tests: `python -I workspace/tests/test_server.py`, `node workspace/tests/pine.test.mjs` (both run in `npm test`).

Not done yet: Databento futures (NQ / ES) in the workspace feed, `request.security` across timeframes, Pine strategies (orders / backtest), alerts, sending closed paper trades into the journal, the economic calendar, a real broker.

## What gets deployed
| Piece | AWS |
|---|---|
| Web app (`frontend/`) | S3 + CloudFront |
| Sign-in | Cognito |
| API (`api.handler`) | HTTP API + Lambda |
| Jobs (`jobs.handler`): downloads, studies, paper, schedule | Lambda (15 min), EventBridge Scheduler |
| Settings, strategies | DynamoDB |
| Candles, footprints, strategy trades | S3 data bucket (gzip JSON) |

Plain Python 3.12, no third-party packages.

## Run it locally
    FAKE_DATABENTO=1 npm start      # synthetic NQ / ES data, any key starting with db-
    npm start                       # your real Databento key
    npm test

## Deploy
Push to `main`: GitHub Actions runs the tests and `deploy.sh`.
